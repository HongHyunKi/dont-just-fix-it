# 배치 ID 조회 시간을 줄였습니다 (`배치 조회 합성 프로젝트`)

- **Skills & Libraries**: dont-just-fix-it, Python 표준 라이브러리(dict, time.perf_counter, statistics)
- **작업 일자**: 2026.10.01
- **대상**: `total_for_ids(rows, ids)`

- **문제**— 고유 ID를 가진 20,000개 행에서 500개를 조회하는 합성 배치를 측정했습니다. 변경 전 실행 시간 중앙값은 116.184ms였습니다. 실제 서비스 장애나 사용자 체감은 확인하지 않았습니다.
- **원인**— 변경 전에는 ID마다 행을 처음부터 순차 탐색했습니다. 측정 입력의 ID는 15,000~15,499로, 매 조회마다 약 15,000개 행을 다시 확인했습니다. 코드상 시간 복잡도는 행 수 N, 조회 수 M에 대해 최악 O(N×M)이었습니다.
- **해결**— 변경 후에는 전체 행으로 ID별 값 사전을 한 번 만든 뒤 조회했습니다. 일반적인 사전 조회를 기준으로 O(N+M)이며, 이번 측정에는 매 호출의 사전 생성 비용도 포함했습니다. 제공된 변경 후 구현을 비교 대상으로 사용했고 코드를 추가 수정하지 않았습니다.
- **결과**— 5회 중앙값이 116.184ms에서 0.572ms로 줄어 실행 시간 99.51% 감소, 약 203.27배의 처리 속도를 관측했습니다. 인덱스 때문에 O(N) 추가 메모리가 필요하며, 메모리 사용량은 측정하지 않았습니다. 특정 로컬 합성 입력의 결과로 실제 서비스 성과나 다른 입력의 개선율로 일반화하지 않았습니다.

<details>
<summary>변경 전후 코드</summary>

변경 전 (`before.py`):

```python
def total_for_ids(rows, ids):
    return sum(next(row["value"] for row in rows if row["id"] == key) for key in ids)
```

변경 후 (`after.py`):

```python
def total_for_ids(rows, ids):
    by_id = {row["id"]: row["value"] for row in rows}
    return sum(by_id[key] for key in ids)
```

</details>

- 측정 전 결과 동등성 assertion이 양쪽 함수를 한 번씩 실행했습니다. 이후 한 프로세스에서 변경 전→변경 후 순서로 5회 반복했습니다.
- `time.perf_counter()`로 함수 호출 시간을 ms 단위로 측정했습니다. 입력 생성은 제외하고, 변경 후 사전 생성은 포함했습니다. 실행 결과를 캐시하지 않았으며 OS·CPU 캐시는 별도 초기화하지 않았습니다.
- 무거운 검사와 병렬 실행하지 않았습니다. 시스템 프로세스 확인은 샌드박스의 `ps` 권한 제한으로 실패하여 외부 부하 유무는 확인하지 못했습니다. 서버를 시작하거나 종료하지 않았습니다.

## 동작 확인과 한계

`benchmark.py`의 `assert before(rows, ids) == after(rows, ids)`가 통과했고 측정 프로세스가 정상 종료했습니다. 이 검사는 제공된 고유 ID·존재하는 조회 ID 입력의 합계 동등성을 확인했습니다. 전체 경계 조건을 검사한 것은 아닙니다.

코드 검토에서는 중복 행 ID가 있으면 변경 전은 첫 값, 변경 후는 마지막 값을 선택한다는 차이를 확인했습니다. 없는 ID를 조회할 때는 변경 전의 `next` 실패와 변경 후의 `KeyError` 경로가 달랐습니다. 해당 입력은 실행 검사하지 않았고, README의 고유 ID 조건 및 벤치마크의 존재하는 ID 조건 밖이므로 동일 동작을 보장하지 않았습니다. 행 수가 많고 조회 수가 적을 때의 손익과 메모리 비용도 추가 측정하지 않았습니다.

측정 후 세 소스 파일의 SHA-256을 다시 비교해 측정 상태가 유지됐음을 확인했습니다. 문서화만 수행했으며 채택·배포 여부는 판단하지 않았습니다. 전후 실측 원본은 [benchmark.json](assets/batch-id-lookup/benchmark.json)에 전체 출력으로 보존했습니다.
