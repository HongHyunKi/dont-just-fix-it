# 초기 화면 로딩과 모달 동작을 함께 고려한 개선 (`dev-portfolio`)

- **Skills & Libraries**: Lighthouse 13.5.0, dont-just-fix-it(기존 자료 문서화)
- **작업 일자**: 2026.09.30
- **대상**: 홈 화면의 한글 폰트·소개 문장과 모달 콘텐츠 로딩

- **문제**— 저장된 baseline 3회 중앙값에서 FCP는 4,059.90 ms, LCP는 7,973.65 ms였습니다. 초기 콘텐츠 표시 지연을 줄이는 작업을 기록했습니다.
- **원인**— 작업 기록은 한글 폰트 로딩과 소개 문장 등장 방식을 개선 대상으로 설명했습니다. baseline 폰트 전송량은 501,012 bytes였습니다. 소스 코드가 제공되지 않아 구조적 원인을 직접 확인하지 못했으며, 각 요소의 독립적인 기여도는 단정하지 않았습니다.
- **해결**— 기록에 따라 한글 폰트 로딩과 소개 문장 등장 방식을 개선했습니다. 모달 지연 로드 실험에서 닫힘 회귀가 발생하여 지연 로드 범위를 콘텐츠 렌더러로 축소한 verified를 최종 비교 상태로 사용했습니다.
- **결과**— baseline 대비 verified의 성능 점수 중앙값은 65점에서 87점으로 22점 올랐으며, LCP는 51.87%, 폰트 전송량은 71.58% 줄었습니다. TBT는 82.50 ms에서 87.50 ms로 증가했습니다. 중간 optimized의 88점은 최종 성과로 사용하지 않았습니다.

## 측정 조건과 근거의 범위

- 2026.09.30 로컬 프로덕션 홈 화면에서 단계별 3회 측정한 기존 자료를 사용했습니다. Lighthouse 13.5.0 CLI의 모바일 시뮬레이션 결과이며 실사용자 지표나 실제 저사양 기기 측정으로 해석하지 않았습니다.
- 모바일 화면 설정은 412 × 823, deviceScaleFactor 1.75였습니다. throttlingMethod는 simulate, RTT는 150 ms, 처리량은 1,638.4 Kbps, CPU 배율은 4였습니다. 나머지 세부 설정도 원본 JSON에 보존했습니다.
- disableStorageReset은 false였으며 저장소 초기화 대상은 file_systems, shader_cache, service_workers, cache_storage였습니다. 실제 브라우저 버전, 실행 명령, 오리진·포트, HTTP 캐시 통제와 머신 사양은 제공 자료에서 확인하지 못했습니다. 에뮬레이션 사용자 에이전트의 Chrome/136을 실제 브라우저 버전으로 단정하지 않았습니다.
- baseline과 verified는 저장된 단계 식별자입니다. 커밋·diff·소스 사본이 없어 당시 측정 코드와 실제 최종 반영 코드의 일치 여부는 확인하지 못했습니다.
- 최초 51점은 JSON이 남아 있지 않아 비교 기준에서 제외했습니다. 데스크톱 99점은 단일 측정이며 변경 전 자료가 없어 개선율을 계산하지 않았습니다.
- 전체 Lighthouse 보고서가 아닌 추출 JSON을 사용했습니다. JSON 안의 reports/... 경로는 당시 보고서 식별 정보이며 해당 파일은 이번 자료에 포함되지 않았습니다.
